# 語り場コレクション v001 — DEMO反映手順

この変更はDEMO専用です。本番ファイル・本番GAS・本番データは更新していません。
公開とGoogle側の設定は手動で行ってください。

**v002更新済み：** イベント保存時のページ再読み込みを修正し、画像はサムネイルから選択する方式になりました。導入済み環境の更新は`README_コレクション保存修正_v002.md`を参照してください。GASの更新は不要です。

## 追加した機能

- 下部ナビのCollection。Home・Schedule・Saved・Contact・Event・Adminを維持し、既存の権限表示も維持します。
- 今年を初期表示する2列のカード一覧、イベント絞り込み、過去年の選択、選択年の獲得枚数。
- 未獲得カードのシルエット、獲得済みカードの詳細、開催日・獲得日時・紹介文・関連ニュース。
- 標準カメラで開けるQR獲得URL、未ログインからの復帰、取得済み、無効・期限外QR、通信エラーと再試行。
- Admin内のコレクション管理。イベント、年別カード、保管済み画像の選択、公開・配布状態を管理。
- 開催回ごとの開催日・配布期間（日本時間）・QR発行・表示・PNG保存・URLコピー・有効／停止。
- 同一イベント・同一年のカードは1種類。同一会員・同一カードの獲得は1件。
- 配布や公開を停止しても、獲得済みのカードと過去の年は会員の一覧に残ります。

## 1. バックアップ

DEMOの現在のApps Scriptソース、スクリプトプロパティ、DEMOスプレッドシート、公開先の`demo/`をバックアップします。
本番プロジェクトでは作業しません。既存の`AUTH_SECRET`、ガチャや通知の設定は変更しません。

## 2. DEMO GASを更新

1. **DEMOスプレッドシートに紐づくApps Script**を開きます。
2. この作業フォルダの`demo/Code.gs`を、そのプロジェクトの既存`Code.gs`へ反映します。
3. スクリプトファイルを追加し、名前を`EventCollection`にして`demo/EventCollection.gs`全文を保存します。`doGet`・`doPost`を重複作成しないでください。
4. 「プロジェクトの設定」→「スクリプト プロパティ」に、以下の3件を追加します。

| プロパティ | 値 |
| --- | --- |
| `COLLECTION_ENV` | `demo` |
| `COLLECTION_SPREADSHEET_ID` | DEMOスプレッドシートURLの`/d/`と`/edit`の間のID |
| `COLLECTION_APP_BASE_URL` | 実際のDEMO公開URL。想定は`https://araragi0040-jpg.github.io/community-news-pwa/demo/`。必ずHTTPS、末尾は`/demo/` |

5. 関数一覧で`setupEventCollection`を選び、一度実行します。
6. 次の4シートが作成されたことを確認します。既存シートの行は移行・削除しません。
   - `CollectionEvents`
   - `CollectionCards`
   - `CollectionClaims`
   - `CollectionQrs`
7. `COLLECTION_QR_SECRET`が自動作成されます。QRの署名に使うため、削除・変更せず保管してください。再実行しても既存の秘密情報は上書きしません。
8. 「デプロイを管理」から、**既存のDEMOウェブアプリを新しいバージョンへ更新**します。現在のURL・実行者・アクセス設定を維持します。

`setupEventCollection`は保存先ID・DEMO設定・シート見出しを確認します。設定不一致ならコレクションAPIは処理を停止します。通常の閲覧APIで新しいシートを自動作成することはありません。

新規トリガーや外部QRサービス、Driveアップロードは使いません。`appsscript.json`への追加設定は、この機能のためには不要です。

`releases/news-demo-event-collection-v001.zip`には次の構成で反映ファイルをまとめています。

- `gas/`：Apps Scriptへ貼り付ける2ファイル。Web公開先へアップロードする必要はありません。

**DEMOのブラウザ保存キーを本番と分離しました。初回はログインし直してください。** 旧キーは削除していません。新しいDEMOの保存済み記事・キャッシュは空から始まり、本番と共有していた旧保存データは自動移行しません。ニュース・アカウント・ポイント等のサーバーデータはそのままです。

## 4. カード画像とイベントの登録

1. `demo/collection-images/`に画像を置き、手動で公開します。
2. `sake-2026.webp`など、半角英数字・ハイフン・アンダースコアの名前にします。PNG/JPG/JPEG/WEBP/GIFに対応します。
3. DEMOでadminとしてログインし、Admin →「コレクション管理」を開きます。
4. 「1. イベント登録・編集」で、日本酒会など継続的なイベント種別を作成します。開催ごとに種別を作り直す必要はありません。
5. 「2. 年ごとのカード登録・編集」でイベント・年を指定し、サムネイル一覧から画像を選択します。
   - 一覧に見当たらなければ「画像一覧を更新」を押します。
   - パスの手入力は不要です。
   - 画像プレビューが表示されることを確認します。
6. 一覧公開・配布有効を必要に応じて設定します。関連ニュースは任意です。

カード画像は元の縦横比を維持し、全体を表示します。未獲得の会員向けAPIには画像パスを返しませんが、画像自体は静的な公開ファイルです。URLを知る人の直接アクセスまで制限する仕組みではありません。

獲得済みカードのイベント・年・画像パスは変更できません。**同じファイル名の画像を上書き・削除することも避けてください。** 翌年は新しい画像名と年別カードを追加します。

## 5. QRの発行と担当者への共有

1. 対象カード、開催日、配布開始・終了を指定します。全て日本時間です。開催日はカードと同じ年にします。
2. 「新しいQRを発行」を押します。
3. QRをPNG保存するかURLをコピーし、担当者へ手動で共有します。
4. 担当者は会場でQRを提示します。担当者にadmin権限は不要です。
5. 終了・中止時はQR単位で停止できます。カード全体の配布停止も可能です。

開始時刻は含み、終了時刻以降は無効です。新しいQRの発行だけでは以前のQRは停止しません。再発行時は、不要な以前のQRを停止してください。
同年に複数回開催する場合は、同じカードに別のQRを発行します。会員には最初に獲得した開催日・獲得日時が残り、2回目は取得済みと表示します。

未ログインなら同じブラウザでログインすると獲得を再開します。ログイン後は自動で獲得処理を行います。登録が必要な場合もURLの`#collection-claim=...`を保ったまま、登録後にログインします。
PWAとは別のブラウザで開いた場合、そのブラウザでのログインが必要ですが、履歴は同じ会員アカウントへ保存されます。

静的QRの写真・URL共有による代理取得は完全には防止できません。開催期間を短く設定し、終了時の停止で運用します。GPS・カメラ読み取り機能・ポイント報酬は追加していません。

## 6. DEMO公開後の実機確認

ローカルの自動テストは通っています。ブラウザ目視確認は操作ツールの制限で未実施のため、以下は手動公開後に確認してください。

1. 一般会員・イベント編集者・管理者でナビが表示され、既存項目を操作できる。特に管理者の7項目を320/375/390/430px相当の幅で確認。
2. 初期は今年。未獲得はシルエット。獲得後は画像・枚数・詳細が表示される。
3. 標準カメラでQRを開く。未ログイン→ログイン→獲得、取得済み、期限前・期限後、停止済み、壊れたQRを確認。
4. 同じ会員の複数タブ・端末から同じQRを開き、`CollectionClaims`が1件だけになることを確認。
5. 別開催回でも重複取得せず、別年は別カードとして取得できる。過去年のカードは残る。
6. 一般会員・イベント編集者では管理APIを実行できない。他人の履歴・未獲得画像パスは返らない。
7. Adminからイベント・カード編集、QR表示・PNG保存・再表示・停止・再有効化を確認。
8. 通信を切っても取得完了にならない。復帰して再試行しても重複しない。
9. ニュース一覧・検索・カテゴリ・本文・保存・スケジュール・問い合わせ・記事管理・イベント管理・プロフィール・ガチャ往復・ポイント・分析・PWA更新を確認。

## 8. 復旧・本番への移行

問題があればバックアップしたDEMOのWebファイルとGASバージョンへ戻します。新設した4シートを消さず保管すれば、取得履歴を保持できます。キャッシュが残る場合はDEMOのPWAを再起動します。

今回のGASはDEMO環境だけで動く保護を入れてあります。本番にそのままコピーして使うものではありません。
本番移行はDEMO確認後、改めて本番用の環境判定・保存先・公開URL・秘密情報・キャッシュ名を設定した差分を用意します。本番の正式カードと画像を登録し、本番URLでQRを発行します。DEMOの履歴やテストユーザーは移行しません。
