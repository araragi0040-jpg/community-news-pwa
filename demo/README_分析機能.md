# demo 利用状況の分析

`news_records-main` を基にしたdemo用の分析画面です。既存の本番用分析画面・本番用GAS・レポート管理GASは変更していません。

## ファイルと役割

| ファイル | 役割 |
| --- | --- |
| `demo/app.js` | ログイン状態での利用と記事本文の閲覧をオンラインで記録 |
| `demo/Code.gs` | 履歴の保存・管理者限定の集計API |
| `demo/index.html` | 管理画面に分析画面へのリンクを追加 |
| `demo/sw.js` | 更新されたアプリのキャッシュを配信 |
| `別/news_records-main/demo/index.html` | demo分析画面の入口 |
| `別/news_records-main/demo/styles.css` | 既存の分析画面に合わせた表示 |
| `別/news_records-main/demo/analytics-ui.js` | SVGグラフ・CSVの生成 |
| `別/news_records-main/demo/app.js` | 管理者ログイン・期間指定・集計表示 |

分析画面は `../../../demo/config.js` を共有します。GAS URLの二重管理は不要です。`MODE` が `demo` 以外ならAPI接続を停止します。フォルダの相対配置を維持してください。

## 反映手順

1. **demo用スプレッドシートに紐づく** Apps Scriptを開き、既存の `Code.gs` を、このフォルダの `demo/Code.gs` 全文で更新して保存します。別の `語り場レポート管理/Code.gs` ではありません。
2. Apps Scriptの関数一覧で `setupNewsAnalytics` を選び、一度実行します。必要なGoogleの権限確認は、使用するdemo用スプレッドシートとGASプロジェクトを確認して進めてください。
3. 次のシートとスクリプトプロパティが追加されます。既存の `posts` / `users` の内容は削除しません。
   - `AnalyticsVisits`：日付・匿名化した会員キー。会員ごとに1日1行。
   - `AnalyticsViews`：閲覧ごとのID・日時・日付・匿名化した会員キー・記事ID・記事タイトル・閲覧時のタグ。
   - `AnalyticsMembers`：日付・利用可能会員数・登録会員数・保存日時。
   - スクリプトプロパティ `NEWS_ANALYTICS_STARTED_ON`：計測開始日。
4. 「トリガー」に `snapshotAnalyticsMembers` が登録されていることを確認します。日本時間23時30分頃に1日1回実行し、利用が0人の日も会員数を記録します。設定関数は再実行しても同じトリガーを重複作成しません。トリガー失敗通知が来た場合は実行ログを確認してください。
5. GASの「デプロイを管理」から**既存のdemo用ウェブアプリを新バージョンに更新**します。新しい別デプロイを作らず、現在のURL・実行者・アクセス設定を維持してください。
6. `demo/app.js`、`demo/index.html`、`demo/sw.js` と `別/news_records-main/demo/` の4ファイルを、既存のWeb配信先へ同じ相対配置で反映します。`demo/tests/` とこのREADMEは配信に不要です。
7. demoニュースを再読み込みします。管理画面の「利用状況を分析 ↗」から開くか、`別/news_records-main/demo/` を開きます。**demo用の管理者アカウント**でログインします。

既存の `別/news_records-main/index.html` は引き続き本番用です。今回追加した `/demo/` を使用してください。

## 指標の定義

- 利用人数：ログイン操作の有無にかかわらず、ログイン済みでアプリを表示した会員。複数端末も同一会員は同じ日に1人。初回表示、タブ復帰、操作時、表示中の1分ごとの日付確認で記録します。分析画面を開くだけではニュース利用に加算しません。
- 利用率：その日の利用人数 ÷ その日に記録した利用可能会員数 × 100。会員数は日次トリガーに加え、利用記録・新規登録・分析更新時にも当日分を更新します。過去日の会員数は現在値で上書きしません。
- 平均日次利用率：選択期間中の日次利用率の平均。分母が未記録の日や利用可能会員数が0人の日は計算から除き、画面には `—` を表示します。
- 記事閲覧回数：公開記事の本文を開いた回数。再閲覧は加算し、編集プレビューは対象外。イベントIDの重複送信は加算しません。
- 記事閲覧人数：選択期間中、対象の記事を開いた会員の重複を除いた人数。複数の記事を読んでも全体では1人。記事ごとの人数の合計とは異なります。
- 日・週・月の人数：各期間内で重複を除きます。週は月曜始まり。月・週の利用率は、その期間に含まれる日次利用率の平均です。登録会員数のグラフは各期間の最後に記録された値です。
- 記事ランキング：**選択期間中に発生した閲覧**を集計します。公開日での抽出や、従来の累計値の合計ではありません。0閲覧の公開記事も表示します。記事を削除しても既に記録された閲覧履歴は残ります。
- 記事・タグのフィルター：記事の閲覧回数・人数・ランキングに適用します。アプリ全体の利用人数・利用率は変わりません。タグは閲覧時の情報を使用します。
- 登録会員数と100人目標：現在の登録済み会員IDの数（停止中を含む）。利用率の分母は `status=active` の会員のみです。管理者・イベント編集者も一般会員と同様に含めます。
- テスト専用会員：`users` に追加される `analyticsExcluded` を `TRUE` にすると分析対象から除外できます。指定後の記録と会員数に適用し、既存の過去履歴を遡って削除はしません。従来の記事累計カウンターは別管理です。

全て日本時間で集計します。オフライン時の記録・通信復帰後の過去分の送信はしません。過去の累計カウンターから日別データを推測せず、計測開始日より前はグラフに補完しません。今日の値と初日の値は、その時点までに計測できた途中経過です。

## 保存と運用

履歴の自動削除処理はありません。スプレッドシートのバックアップを定期的に取ってください。無制限の保存を保証するものではないため、長期運用でシート容量・集計時間が増えた場合は、履歴の保管先を分けるなどの対応を検討できます。想定の1日30閲覧なら閲覧履歴は年間約11,000行です。

会員キーは既存の `AUTH_SECRET` を使って匿名化します。認証用シークレットを変更すると会員キーも変わるため、変更前後にまたがる期間の人数が重複することがあります。集計APIは個人キーや氏名、メールアドレス、閲覧者一覧を返しません。元スプレッドシート自体の共有範囲は既存の管理者向け設定を維持してください。

会員数のトリガーが実行されなかった日の分母は推測せず未記録として表示します。会員の停止・削除があると、同日の最後の利用可能会員数と、その日に既に利用した人数との関係で利用率が100%を超える場合があります。

## ローカル検証

追加ライブラリは不要です。プロジェクトのルートで実行します。

```powershell
node --test demo/tests/analytics.test.cjs demo/tests/analytics-client.test.cjs
node demo/tests/preview-server.cjs
```

プレビュー：`http://127.0.0.1:4173/別/news_records-main/demo/`

画面確認用ログイン：`preview@example.test` / `preview`

プレビューサーバーは127.0.0.1だけで待ち受け、架空データを表示します。Googleにはアクセスせず、実際のスプシは変更しません。終了はサーバーのターミナルで Ctrl+C。通常の静的配信時にはこの架空データは表示されません。

ローカル検証はGASサービスを模したメモリー内の環境によるものです。実際のGoogle環境での実行・権限・トリガーは、上の反映後に確認してください。

## 反映後の確認

1. 同じ会員でdemoニュースを複数回開き、当日の利用人数が1人のままであること。
2. 同じ記事を2回開き、選択期間の閲覧回数が2増え、閲覧人数が1人になること。
3. 別の会員で利用し、管理者の更新ボタンで人数が増えること。
4. 記事やタグのフィルターで閲覧指標が変わり、全体の利用人数は変わらないこと。
5. 日／週／月のグラフ、日別表、2種類のCSV、会員100人への進捗を確認すること。
6. 一般会員では分析API・分析表示を利用できないこと。
7. 翌日に `AnalyticsMembers` の当日行が追加されること。
